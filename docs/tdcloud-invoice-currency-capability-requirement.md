# TDCloud 商户收款订单币种元数据开放能力需求

## 归属和背景

订单币种、最小单位及精度由 TDCloud 平台规定。外部商户只提交自己的业务订单金额与币种，不应配置、重新定义或人工抄写 TDCloud 的精度规则。插件负责读取平台权威数据、精确换算、固定支付尝试快照及核对结果。

## 已核对的缺口

- `GET /openapi/v1/merchant-payment-channels` 返回收银台内部支付方式，当前 `MerchantCollectionChannel` 没有 `currency_decimals`。内部支付方式币种也不能代表所有可收款订单币种。
- 平台币种目录 `/system/financial/currency` 要求管理员身份，商户插件不应使用管理员凭据调用。
- 商户建单结果包含 `currency_decimals`，但调用方需要在提交 `amount_minor` **之前**确定单位；事后校验不能防止第一次建错金额。

以上依据当前本地 TDCloud 实现，新增接口的具体路径、字段和权限由 TDCloud 确定。本需求不直接修改 TDCloud。

## 需要的外部行为

1. 商户服务端凭据在建单前可获取该商户允许的**订单币种**及对应整数精度，数据与建单实际使用的权威币种规则一致。可返回完整目录或按币种查询，不要求公开内部支付方式 ID。
2. 明确禁用币种、未知币种、权限不足及临时不可用的行为；零位精度是有效值，缺失精度不能与零混同。
3. 明确精度变更与缓存规则。已创建订单的精度保持固定；如平台允许精度调整，需要提供防止“读取后、建单前规则变化”导致错收金额的契约，例如版本条件校验或显式金额单位校验，由 TDCloud 选择实现。
4. 使用商户开放授权，不要求平台管理员登录或消费者登录来读取这份数据。

## 插件边界与验收

- 商户表单只配置连接、凭据和通知选择，不填写币种精度。
- 仅用商户服务端凭据自动获取数据；宿主订单币种决定查找项，TDCloud 收银台决定支付方式。
- USD 两位、TDC 八位、JPY 零位示例覆盖精确换算；未知、缺失、非法元数据在建单前阻止支付，不猜值、不四舍五入。
- 超时重试、插件重启和元数据变化后，原尝试继续使用已保存的精度、金额和幂等键。
- 查单和通知继续校验原单号、引用、金额、币种及精度，重复确认只结算一次。
- 使用最终 TDCloud 实际接口进行联调；模拟元数据或旧手动配置不能作为自动获取已完成的证据。
