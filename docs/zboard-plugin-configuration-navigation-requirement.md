# 插件配置页面的通用业务导航需求

## 页面职责

插件管理负责安装、启停、版本与卸载。插件提供的业务设置（例如支付渠道）应能通过管理员日常业务导航访问。配置页可以继续从插件详情进入，两个入口访问同一配置数据与授权流程。

本需求适用于任意插件配置页，不涉及支付提供商、渠道字段、订单或结算逻辑。

## 已核对的边界

- 宿主支持插件声明业务页面及菜单位置。
- 但 `backend/internal/plugins/manifest.go` 明确拒绝 `purpose: configuration` 页面声明 `menu`；`navigation.go` 也不注册配置页面菜单。
- `sessions.go` 的 `configurationSession` 只接受管理员配置会话；前端 `PluginFrame.vue` 同样只让配置会话调用 `config.*`。
- 直接把插件配置页改成业务页，会失去配置桥接授权。插件不能靠改页面名称或借用业务会话绕过规则。
- 截图中的重复“插件市场 / 插件管理”由宿主导航组件渲染；插件的 `ui/config.html` 与入口模块没有这些导航。

因此插件可以自行改进内容与渠道类型选择，但无法仅靠当前清单注册一个具备现有配置权限的业务菜单入口。本文件只提出需求，不直接修改 ZBoard。

## 所需通用行为

1. 配置页面可以声明菜单位置，或通过宿主已有菜单管理将其放到适合的业务分组；菜单归属来自插件声明或站点配置，不由宿主按插件 ID 写死。
2. 菜单入口打开同一插件配置页，继续创建管理员配置会话，使用现有配置权限、脱敏、加密存储、版本冲突和生命周期机制。无需向普通业务会话开放 `config.*`。
3. 插件详情中的配置入口与业务菜单共享同一数据源；不能生成两套渠道配置或要求第二次填写凭据。
4. 页面标题、面包屑及分组导航反映实际业务位置，插件市场和插件管理仍可通过各自入口访问。
5. 同一视口不重复呈现相同分组导航；桌面和移动布局都需检查。

## 验收条件

- 使用不含支付提供商字段的通用测试插件，其配置页可按声明放入业务菜单并打开。
- 菜单显示、隐藏、移动遵循现有菜单治理；刷新、重登及升级后位置正常。
- 两个入口读取同一配置，保存后另一入口可见更新；省略密钥的编辑不丢失原密钥。
- 非管理员不能获得配置会话；原配置能力限制及冲突校验不变。
- 插件停用时的配置入口沿用当前宿主允许配置的生命周期规则；卸载后入口不再开放。
- 桌面与移动端各自只有一份相应分组导航，业务设置不会被标成插件管理页面。
