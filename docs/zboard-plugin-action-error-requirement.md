# ZBoard 通用插件动作错误透传需求

> 2026-10-14 状态：ZBoard 已发布公开 `NewActionError` 契约，见 SDK 的 `pluginapi/v1/actions.md`；线上已显示版本 `v0.0.3-dev.202610140556`。插件侧已适配显式公开业务错误，以下内容保留为需求与验收基线。

请先评估现有插件契约是否已经覆盖以下行为，确认缺口、兼容性及最小调整方案。若已有能力足够，请明确公开接口和正确使用方式；若确有通用缺口，再由 ZBoard 对话推进宿主调整。

## 问题与目标

当前 `backend/internal/plugins/page_actions.go` 调用原生插件动作后，将除超时外的 RPC 错误统一转换为 `ErrUnavailable`。线上经 HTTP 和 UI 桥接调用，页面会收到泛化的 HTTP 503，插件提供的业务原因无法展示。插件直接返回的 JSON 结果可以传递，但现有通用动作控件还需要明确如何识别和处理业务失败。

需要开放一套通用、可安全展示的动作结果与错误契约，让使用方区分业务拒绝、可重试的业务状态，以及宿主授权或运行故障。适用范围包括页面动作、插槽动作及其宿主控件。

## 职责边界

- 插件判断自己的业务状态，提供稳定错误码、公开说明及重试建议。具体业务状态机、外部系统协议和补偿策略由插件维护。
- ZBoard 定义并校验通用契约，贯通原生 SDK、HTTP、UI 桥接和通用动作控件，按纯文本展示公开说明。宿主不解释插件业务错误，也不替插件决定业务状态、有效期或重建规则。
- 宿主的认证、授权、会话、资源限制和进程管理继续由宿主控制。插件结果不能覆盖宿主权限错误、扩大访问范围或伪造宿主业务成功。
- 本需求不要求放宽权限、直接返回任意异常字符串、改变核心业务事务，或实现任何外部服务适配。

## 契约评估要求

1. 区分动作成功与业务失败。业务失败至少能表达稳定错误码、面向用户的公开说明、是否允许用户重试。字段名称、编码方式和 HTTP 状态规则由 ZBoard 根据现有 SDK 评估确定，并公开文档。
2. 优先复用已有结构化结果或标准错误机制。不要仅转发原始 RPC 错误文本，也不要根据错误说明中的关键词推断业务状态。
3. 区分宿主错误和插件错误的来源或命名空间。宿主认证、权限和会话错误具有独立规则；插件的公开错误码不能冒充它们。插件动作失败不能触发主账户全局退出。
4. 保持结果语义在各层一致。即使采用成功 HTTP 响应承载业务失败，桥接和宿主控件也必须识别失败，不能继续执行成功后的导航或界面更新。返回错误 HTTP 状态时，也应保留规范化业务信息。
5. 限制字段格式、长度及结果大小。公开说明按纯文本处理；内部错误、堆栈、凭据、配置及第三方原始响应不直接展示。非法或未知错误安全降级为通用说明。
6. 明确重试语义。允许用户重试不代表宿主可以自动重放有副作用的动作，也不代表该动作具备幂等性；自动重试仍遵守现有动作契约。
7. 宿主为动作预留窗口或临时资源时，失败应清理这些资源，恢复可操作状态并保留用户输入。插件业务失败不得执行成功分支。
8. 保持旧插件兼容。未采用新错误契约的插件仍可运行，使用通用失败说明；若需要协议版本或能力协商，请在评估中明确，不要求所有插件同步升级。

## 验收条件

使用独立测试插件返回通用业务结果，不依赖任何外部渠道或业务订单。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 可重试业务失败 | 从原生 SDK 经真实 HTTP、UI 桥接到页面，公开错误码和说明保持一致，重试标记可读取，页面不只显示 HTTP 503 |
| 不可重试业务失败 | 显示明确说明，保留失败语义，不被当作成功或自动重放 |
| 失败后的控件和资源 | 忙碌状态恢复、用户输入保留、预留空白窗口关闭、成功导航及后续动作不执行 |
| 原生进程退出或调用超时 | 使用宿主运行错误规则，清理临时资源，不伪装成业务成功 |
| 权限拒绝或插件会话失效 | 保持宿主授权约束，不受插件字段覆盖，不误触发主账户全局退出 |
| 响应到达前会话撤销或插件升级 | 按现有生命周期规则拒绝旧结果，不更新新页面或执行成功分支 |
| 超长文本、HTML、非法字段和内部异常 | 安全校验或降级，文本不作为 HTML 执行，内部信息不泄漏 |
| 旧版插件和现有成功动作 | 保持兼容，成功返回、导航和授权行为无回归 |

验收必须覆盖完整 HTTP 和 UI 传递链。只测试原生 SDK 能返回错误，或只测试前端模拟数据，不算完成。

## 评估和交付

请先给出现有覆盖情况、建议契约、最小修改范围、兼容与安全影响，再推进确认必要的通用调整。交付内容包括公开 SDK/桥接文档、上述场景的自动化回归，以及哪些结果已在真实界面验证。

本次宿主调整由 ZBoard 对话负责；插件对话在公开契约确定后负责适配。请保留两边已有未提交工作，不跨仓库代改，不顺带提交、发布或部署。
